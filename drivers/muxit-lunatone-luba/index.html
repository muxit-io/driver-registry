Changelog

## 0.4.0 - **Every property and action is renamed, and names now start with the layer they talk to:** `usb…` for the Lunatone interface, `bus…` for the whole DALI line, `unit…` for one DALI address. **If you have scripts or dashboards for 0.3.x, rename the calls:** `open`/`release` → `usbOpen`/`usbRelease`, `interfaceInfo` → `usbInfo`, `busStatus` → `busRefresh` / `busScan`, `scan` → `busScan`, `assignAddresses` → `busAssignAddresses`, `sendRaw16` → `busSendRaw`, `setLevel` → `unitSetLevel`, `queryActualLevel` → `unitLevel`, `readStatus` → `unitStatus`, `readSettings` → `unitSettings`, `storeSettings` → `unitConfigure`, `setShortAddress` → `unitSetAddress`, `setDimmingCurve` → `unitSetCurve`, `identify` → `unitIdentify`, `reset` → `unitReset`, `readD4i` → `unitD4i`, `readMemoryBank` → `unitMemoryBank`, `query` → `unitQuery`; properties `connected` → `usbConnected`, `port` → `usbPort`. - Removed as redundant: `off`, `recallMax`, `recallMin` (use `unitSetLevel`, 0 = off), `queryStatus` (part of `unitStatus`), `queryDimmingCurve` (part of `unitSettings`), `lineStatus` (the heartbeat keeps `busPowered` live), `writeMode` and `interfaceSettings` (now `usbInfo().settings`). - **The USB link is watched: an unplugged interface now shows as disconnected.** Previously `connected` stayed `true` until `release`, because the serial port still reads as open after the device disappears. A heartbeat (READ STATUS every `heartbeatMs`, default 2000) checks that the interface answers. A failed write or two consecutive LUBA timeouts mark the link as lost. New: `usbState` (`ok`, `notFound`, `portBusy`, `noResponse`, `released`, `notConfigured`, `closed`, `error`), `usbMessage` and a live `busPowered`. - Auto-reconnect: while the link is down the driver reopens the port every `reconnectMs` (default 3000), so plugging the interface back in recovers on its own. `usbRelease` stops this until `usbOpen`, so the MultiOne hand-over is not affected. A missing or busy interface at startup no longer stops the connector from loading. - The dashboard values moved from the template into the driver: `status` (`OK`, `FAIL`, `NO UNITS`, `NO DATA`, `NO BUS`, `NO USB`, `PORT BUSY`, `NO RESPONSE`, `RELEASED`, `NO PORT`, `OFFLINE`), `statusText` (now with the failures), `lastUpdate`, `units` (now the unit list, `level` instead of `actualLevel`), `unitCount`, `unitLevels` and the writable broadcast level `busLevel`. The `dali` template is now only config and AI instructions; its short-name methods are gone because driver actions take positional arguments directly. - `unitConfigure(3, {maxLevel: 200})` works from a script. The old `storeSettings(3, {…})` silently wrote nothing, because the trailing object was merged as options. - "DALI status" dashboard rebound to the new names, with the new states. One status box replaces the Summary / Failures pair.
